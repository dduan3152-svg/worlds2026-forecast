# S16 / 2026 全球总决赛：可复现概率模型 v1.0.0

## 本版结论及适用范围

信息截止为 **2026-10-23 15:25:50，北京时间（Asia/Shanghai，UTC+08:00）**，等价于 `2026-10-23T07:25:50Z`。当时瑞士轮尚未开始；首场为北京时间10月24日01:00。KC已通过入围赛，C9、FUR、MVK已淘汰。已发生的入围赛结果进入历史数据，不会被重新模拟。

本版实际训练了队伍级 Bradley–Terry 基线，并实际运行 **100,000 次基线完整赛事模拟、15组各100,000次敏感性模拟，以及200次重新拟合×10,000次赛事模拟**。GEN的基线夺冠概率为34.13%，HLE为16.287%，BLG为13.761%，T1为12.848%。这些数值是计算结果，适合表述为约34%、16%、14%、13%，不是已知的真实胜率。

GEN的90%系列簇加权Bootstrap模型重采样区间为15.9%—46.6%；178/200次重采样中仍为夺冠概率最高的队伍。后一个89%是“在重采样模型中排名第一的频率”，**不是89%的夺冠概率**。所有已测试单项情景均保留GEN为首选，但参数及数据组成改变会显著改变概率。

这是一个有真实赛果训练、时间回测和可审计赛程模拟的简单模型。它不是选手、版本、BP及心态的完整模型，也不能凭单届世界赛验证冠军概率校准。

## 快速复现（离线）

使用Python 3.12及`requirements.txt`中记录的依赖，在解压目录执行：

```bash
python -m pip install -r requirements.txt
python src/run_analysis.py --phase all
python src/verify_outputs.py
python src/build_figures.py
python src/build_report.py
```

前三个建模阶段也可独立运行：

```bash
python src/run_analysis.py --phase fit
python src/run_analysis.py --phase simulate
python src/run_analysis.py --phase uncertainty
```

`--phase all`使用已冻结的本地输入，不联网，不调用新闻排名或此前聊天中的概率。代码使用NumPy的`default_rng`。基线/敏感性种子为`20261023`，Bootstrap根种子为`20261024`；各重采样模拟种子保存在`outputs/bootstrap_log.json`。同依赖版本及相同输入可复现统计输出，浮点优化在不同平台可能有极小数值差异。

输入从原始快照重新清洗与官方对账：

```bash
python src/fetch_history.py --reconcile-riot --cutoff 2026-10-23T07:25:50Z
```

这是离线重建命令。仓库只保留本地快照处理功能，联网下载和接口认证代码已移除。

## 输入、来源及缺失处理

`data/history_chaincc_teams_2026.csv.gz`是实际取得的ChainCC原始快照：19,506条队伍记录，即9,753局。来源页面更新时间为2026-10-22，许可CC BY 4.0，归属ChainCC（chaincc.lol）。这是一个开放的第三方数据集，不能写成“Oracle's Elixir成功下载”或“Riot认证逐局全集”。

清洗保留2,849条真实逐局；另外两局只取得官方系列赛比分残余，单独存入`history_supplements.csv`，不补造游戏ID、局序、阵容、地图边或版本。对账时统一了官方KRX与Kiwoom DRX的DRX代码；1004场官方系列赛中1002场比分完全一致，两场各缺一局，没有比分冲突。

主分析采用2,599个实际比赛结果：2,597条逐局加2条官方残余，1,005个系列赛，61支队伍，范围为2026-01-14至2026-10-18。包含六大赛区、LPL资格赛、FST、MSI、Americas Cup、EWC主赛及Worlds入围赛。EWC资格赛和DCGI只进入扩展赛事敏感性分析。`outputs/data_audit.json`记录逐赛事数量。

已知跨赛区比较为189局、66个系列赛，另有4局因Team Secret赛区身份未确认而保留UNKNOWN。TS与TSW不因为名字相近就合并。所有队伍构成一个连通比较图，但“连通”不代表跨赛区差异估计足够精确。IG和CFO在主样本没有直接国际比赛，跨区估计依赖同赛区其他队伍的连接。

选边、版本标签和五人阵容各缺2/2599（约0.08%），均为补齐的结果计数。另从ChainCC公开player文件提取了全部实际局的完整五人，和双队元数据逐项对齐；这些历史阵容已连接到模型输入表，但冻结主模型不显式估计阵容系数。AL报道的本届五人在样本中只有52/142局，IG为33/124局；TES当前369/Tian/Creme/JackeyLove/Zhuo组合为0/140局，不等于选手本人没有经验。原始版本标签如16.20按来源保留，官方本届比赛版本为26.20，两者不未经核实地重命名混用。

追加的两组阵容情景把“历史五人与截止时已知当前五人不同”的观察对每支不匹配队伍减权至0.5或0.25；两队均不匹配时乘积为0.25或0.0625。两条未知缺局阵容保持中性权重，不捏造人员。当前世界赛名单只用于最终截止时的情景拟合，绝不回填历史回测。这些减权系数未验证，不等于测得的换人收益，结果保存在`outputs/lineup_sensitivity_log.json`。GEN在两组情景中分别为30.8%和28.8%，仍为首选。

源数据的`WLDs`包含12局LPL资格赛和22局Worlds入围赛，已分开标记；`WLRQ`是另一项青训/草根赛事，未作为Worlds资格赛纳入。逐局表`best_of=1`仅表示一局观察单位，不表示该系列赛本来是BO1；真实系列赛制见官方系列表。

去重以`game_id`为单位：同一局原始两行必须蓝红各一、赛果互补、对手互指、元数据一致，最后只保留一条对局记录。系列赛ID由实际比赛编号和时间连续性派生，并保存方法；官方比分只用于核对及补足缺失差额，绝不重复加入整场比分。

## 模型定义

训练对局k的概率为：

`p_k = sigmoid(theta_A - theta_B + beta_blue * side_A)`

其中蓝方`side_A=+1`、红方`-1`，两条未知选边的残余观察为0。最小化逐局负对数似然的时间加权和，加上L2正则：

`L = Σ_k w_k * [-wins_A*log(p_k) - wins_B*log(1-p_k)] + lambda/2 * (Σ_i theta_i² + beta_blue²)`

`w_k = 2 ** (-age_days / half_life_days)`。

主模型使用半衰期120天、正则λ=0.25、温度T=1.5。参数由2026年5月、6月、7月三个按月向前验证折选择，目标为合并Log Loss最小；候选网格在`config.json`中。8月及之后测试结果不用于选参数。最终模型再利用截止前全部主样本重新拟合。

蓝方系数β约0.1988，它是本数据下控制队伍水平后的关联项，不是蓝方的因果优势估计。未知未来选边采用明确的50:50边际化：

`P(A胜单局) = 0.5*sigmoid((theta_A-theta_B+beta)/T) + 0.5*sigmoid((theta_A-theta_B-beta)/T)`。

未来First Selection的选择策略没有拟合；蓝方也不等于必然先选英雄。上述均值是一个公开假设，不是假装知道某队实际拿到哪一边。矩阵是赛前、未观测BP、队伍级历史实力的概率投射；不承诺本届每局最后提交的阵容都等于报道中的首发。

BO3、BO5默认在固定实力条件下各局独立、单局p恒定：

`P_BO3 = 3p² - 2p³`

`P_BO5 = 10p³ - 15p⁴ + 6p⁵`

系列赛内相关性ρ=0.10、0.25仅用于情景压力测试。此时每个系列赛有一个Beta分布潜在胜率，均值仍为p，κ=1/ρ−1，α=κp；用其二至五阶矩积分上述多项式。ρ没有从数据估计，不应解释为测得的心态或Fearless效应。每个系列赛独立重新抽潜在状态，不是跨整个赛事持续的状态模型。

## 时间回测与校准

调参验证范围为5月至7月，共744局、270个系列赛。最终留出测试为8月1日至截止前，共711局、248个系列赛；BT和Elo都在每个测试月份起点使用过去完整系列赛训练，然后冻结到该折结束。Elo K=20、尺度400，按完整系列赛批量更新，不能使用同一系列赛前局的结果预测其后局。

所有真实逐局及补齐残余使用同一系列赛簇，`date`统一为系列开赛时间，另存完整结束/可用时间`series_end`；跨训练/测试边界的整系列赛排除。原始逐局日期仍保存在`game_date/source_date`。输入中没有目标对局的经济差、击杀、赛后排名或其他赛后特征。

| 模型 | 准确率 | Brier | Log Loss |
|---|---:|---:|---:|
| 时间衰减BT | 62.6% | 0.2270 | 0.6447 |
| 基础批量Elo | 60.5% | 0.2319 | 0.6552 |
| 恒定50% | 50.0% | 0.2500 | 0.6931 |

准确率中精确50%预测按随机破同分的50%期望记分。以上只是这份留出集的点估计比较，没有声称差异具有统计显著性。Brier和Log Loss同时包含区分能力等信息，较低的Brier本身不等于校准更好。

校准表改用“模型看好的一方是否取胜”，每局仅计一次：50–60%档394局，平均预测54.7%、实际57.4%；60–70%档228局，64.7%/62.7%；70–80%档79局，73.3%/83.5%；80–90%档只有10局，81.4%/100%；90–100%档无样本。高概率区明显缺样本，不能宣称完美校准。相同系列赛内各局相关，局数不等于独立样本量。

国际留出仅22局、6个入围赛系列，Brier约0.247，接近0.25基线。国内占主导的总回测无法证明跨赛区或冠军概率校准。回测使用当前冻结快照按事件时间回溯，不是逐个历史时刻保存的原始网页快照；历史资料修正带来的风险未完全消除。

## 真实赛制与抽签近似

瑞士轮固定真实首轮；第二轮起同战绩配对，三胜晋级、三负淘汰，晋级或淘汰局BO3，其余BO1。无重复交手原则有“根本不存在合法签时由官方豁免”的窄例外。四分之一决赛两支3–0分别面对两支3–2且分居两个半区，剩余四队随机配对，淘汰赛均BO5，不额外强加同赛区回避。

官方文本规定抽到冲突时移到下一可用位置，并防止后续放位被迫冲突，但没有提供完整机器算法。主实现先均匀抽取小组内抽球顺序，再按最早可行槽位放入并检查本组剩余槽位能完整配对；枚举最多8!种球序得到实际诱导分布。**没有默认所有合法签表等概率**。均匀合法匹配是单独的抽签敏感性情景。

First Selection按2026专项规则：获得权利的一方选择地图边或BP先后，另一方选择另一维度；瑞士首局高赛区种子优先，八强首局好战绩优先（同战绩按抽签顺序），半决赛及决赛掷币，系列赛后续局败方优先。本版没有用数据不足的First Selection策略制造某队额外优势。Fearless证据的具体边界以`data/rules.json`为准，模型不添加主观英雄池分数。

每次模拟抽取胜负，而非总判优势队获胜；基线内队伍实力始终固定，不因模拟赢下一场而上调评分。完整实现支持锁定已公布Swiss对阵、已结束Swiss结果、八强签表和淘汰赛结果。

## 不确定性与校验

基线有限模拟次数的标准误为`sqrt(p*(1-p)/100000)`。GEN的95%蒙特卡洛误差约±0.3个百分点。这只反映重复随机模拟的数值误差。

模型重采样以完整系列赛为簇，抽取独立Exp(1)权重并归一到均值1，固定已选超参数，重新拟合队伍及选边系数。200组参数各运行10000次完整赛事，每条赛程内参数固定。报告5%和95%分位数，称“90%模型重采样区间”；不是已经验证覆盖率的频率学置信区间，也没有包含所有模型风险。每组内部模拟的最大标准误仍可达0.5个百分点。

模型选择、数据系统性误差、未估计阵容/版本影响及抽签执行细节，不能由该区间自动覆盖。另列的敏感性范围是**情景范围**，不是统计置信区间；没有把互不相关的情景端点拼成概率分布。

基线全部100000次检查通过：每次33场Swiss和7场淘汰赛；八强、四强、决赛、冠军名额分别8/4/2/1；无错误战绩配对、无重复Swiss对阵、无错误半区；未触发重赛豁免。完整19队概率之和精确为8、4、2、1。对每队均有冠军≤决赛≤四强≤八强；两两概率互补。额外以首轮独立胜负的解析公式核对第二轮对手概率。

### 比赛结束后更新

1. 复制此目录为新版本（例如v1.0.1），保存旧输入和输出；不要覆盖本版预测后再称它为赛前预测。
2. 同步修改`config.json`的UTC/北京时间截止及`data/known_state.json`的`cutoff`。如果只更新已知状态而不取新逐局数据，模型战力仍是旧估计，应明确称为“条件于新赛果的旧模型更新”。
3. 在独立环境准备并审核新的队伍、选手和官方系列赛快照，保存为新的数据版本。然后运行 `python src/fetch_history.py --reconcile-riot --cutoff 新的UTC截止`、`python src/prepare_model_data.py` 和 `python src/extract_historical_lineups.py`，完成离线清洗与阵容匹配。检查官方比分对账和所有缺失/矛盾；完全缺失的系列赛需人工审核。仓库不含联网抓取和认证功能。
4. 把已经结束的Swiss结果写入`known_matches`，每项包含`round,a,b,winner`；已公布完整轮次写入`announced_rounds`。当前轮可部分结束，既往轮必须完整连续，不能只挑选有利赛果。
5. Swiss结束后，按实际半区顺序在`quarterfinal_bracket`写四组配对；前两组同半区，后两组另一半区。淘汰赛已结束结果写入`known_knockout`，包含`stage`（quarterfinal/semifinal/final）、`a,b,winner`。
6. 运行`python src/run_analysis.py --phase all`。调参/历史测试边界默认维持本版配置，避免追着后续比赛结果反复调到“看起来正确”；更新最终拟合时才加入截至新时点的正式赛果。如要重新设计超参数/回测协议，应另记模型版本。

查看隔离的更新演示：

```bash
python src/update_state_example.py --n 10000
```

该脚本从一个**模拟样本**提取已知历史，仅写`examples/`，不覆盖真实状态；示例结果不是官方赛果。它演示固定前两轮并接入第三轮对阵、以及固定全部Swiss和八强签表后继续预测。

`verify_outputs.py`中的解析第二轮校验专用于本版“瑞士尚未开赛”的状态，赛中更新后应使用模拟器自带的条件状态检查，不再把赛前解析公式套用到已发生状态。

模型和模拟器支持以上状态更新；本版PDF的部分赛事叙述与表格说明仍是v1赛前报告模板。更新截止时间或赛事阶段后，需复核并修改`src/build_report.py`中的对应叙述，再生成新报告，不能只替换概率而保留旧的赛前事实。图表从配置和输出读取数据，生成后也应核对标题、条件与标注。
