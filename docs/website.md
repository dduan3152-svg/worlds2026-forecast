# 网站与赛果条件更新

网站位于 `site/`。它展示 16 支瑞士轮队伍的八强、四强、决赛和夺冠概率，支持赛区/战队筛选、BO1/3/5 对阵比较、预测版本切换、概率变化轨迹和 JSON 下载。

## 直接打开独立静态网页

每次导出都会生成 `site/forecast.html`，内嵌页面样式、交互代码、预测数据和可下载的 PDF 报告。直接双击此 HTML 即可使用，无需本地服务、网络或额外文件。

```bash
python src/live_forecast.py --export-only
```

云端每次定时更新后，私有 artifact `private-forecast-website` 也包含这份文件。下载并解压后直接打开 `forecast.html`。独立文件是导出时的快照，不能在离线状态下取得新赛果；有更新时下载新版本。

## 私有预览

在项目根目录、已安装依赖的 Python 3.12 环境中运行：

```bash
python src/live_forecast.py --export-only
python src/serve_site.py
```

打开 `http://127.0.0.1:8766`。服务只监听本机，只提供 `site/` 内容，不开放仓库、登录凭据或文件编辑接口。

若本机已经通过 GitHub CLI 登录，可跟随私有仓库里的最新网站数据：

```bash
python src/serve_site.py --follow
```

`--follow` 每分钟通过本机 GitHub CLI 读取私有仓库的 `site/data.json`，不把 GitHub 凭据发送到浏览器。若 `gh` 不在 PATH，使用 `--gh /path/to/gh`。它只在内存中更新预览数据，不改写仓库文件，也不拉取或覆盖代码。停止服务后再次打开，需要重新启动该命令。

普通 GitHub Pages 网站可能公开可访问，即使源码仓库私有。本项目没有启用 Pages，也没有公开网站部署工作流。公开发布必须另行确认。

## 自动更新

`.github/workflows/forecast.yml` 在每小时 UTC 第 17、47 分钟计划运行（约每 30 分钟一次），实际开始时间受 GitHub 排队影响。北京时间与 UTC 分钟数一致。常规定时更新在 2026-11-15 UTC 结束后停止抓取，仍可在 Actions 中手动运行。

数据源：[ChainCC 公开队伍 CSV](https://chaincc.lol/data/chaincc-teams-2026.csv.gz)。[发布页面](https://chaincc.lol/free/data/) 标注 CC BY 4.0，允许再分发和修改，且不需要账号或 API 密钥。本功能只请求这个固定公开地址；没有恢复 Riot API 客户端或认证功能。保留 ChainCC 署名、许可和处理说明。

流程：

1. 下载公开快照到内存，检查压缩/解压大小、字段、双方赛果互补和局序。
2. 只采纳瑞士轮开始之后、当前时间之前已经结束的本届世界赛比赛。
3. 从逐局结果重建 BO1/BO3/BO5 系列赛。缺局、重复、未知队伍、旧赛果被来源修改时暂停更新。
4. 有新可采纳系列赛或确认签位时，锁定已知结果，用冻结单局胜率矩阵重跑 100,000 次剩余赛事模拟。
5. 在 `live/history/` 添加新版本，更新 `live/status.json` 和 `site/data.json`。没有新赛果时概率保持不变。
6. 把网站打包成私有 Actions artifact `private-forecast-website`（保留 7 天）。此操作不会发布公共网站。

首次安装依赖及自动抓取需要联网；原始建模、冻结数据复现依然支持离线运行。

## 更新边界

- **这些是赛果条件更新。** 战队实力仍来自 2026-10-23 冻结模型，新增比赛没有进入重拟合；假设对阵的 BO1/3/5 胜率因此保持固定。晋级和夺冠概率随已知赛果变化。
- 本站不提供局内实时胜率。ChainCC 没有承诺实时更新；检查频率不等于源数据发布频率。页面分别显示检查时间、来源最新比赛时间和预测赛果截止。
- 首轮对阵已知，可在每个系列赛结束并进入数据源后更新。第二轮起，如没有完整官方对阵表，必须等该轮所有系列赛结束；否则只保存等待状态。这样不会把未知抽签当成已知事实。
- 瑞士轮结束后，须确认八强签位及半区顺序，之后淘汰赛赛果可继续自动采纳。不得从比赛时间顺序猜半区。
- 冻结版的 Bootstrap 区间不沿用到新预测。当前赛中版本只计算条件模拟概率，没有重做模型不确定性分析。
- 若源数据撤回或修正已采纳赛果，自动任务失败并保留上一有效预测。需要先人工核查并设计明确的更正记录，不能静默改旧版本。

## 录入已公布签位

在 `live/settings.json` 中填写真实已公布的对阵及来源。瑞士轮 `announced_rounds` 的键为轮次字符串（2–5），值为该轮全部配对；不能只给一场。`quarterfinal_bracket` 为四组八强对阵，前两组同半区、后两组另一半区。首次录入八强前，来源中应已包含全部 33 场瑞士赛果。

`draw_source_url` 为官方公布签位的 HTTPS 页面，`draw_as_of` 为公布时间（带时区 ISO 8601）。其余设置保留默认值。提交修改后在 Actions 手动运行 `Refresh private forecast` 即可核验和重算；验证失败时不会生成新版本。

这个设置文件默认不填任何后续签位。测试中的对阵全部来自合成模拟，不会被自动导入真实网站。

## 数据与版本

- `outputs/`、`data/` 和原始报告保持冻结。
- `live/history/*.json` 记录新预测、采纳赛果、输入哈希与前一版本哈希。
- 历史版本采用追加方式；CI 检查已有版本没有被修改或删除。哈希链用于发现篡改，不是第三方可信时间戳。
- `site/data.json` 为整个网站的数据入口，不包含原始 API 快照、账号信息或密钥。
- `site/report.pdf` 在导出时从冻结报告复制，不重复提交 Git。
- 冻结发布包清单包含网站代码，但不跟踪动态预测文件。动态文件由 `src/check_live.py` 单独校验。

```bash
python src/live_forecast.py --fetch
python src/check_live.py
python -m unittest discover -s tests -v
```

手动测试本地快照可使用 `--input 文件路径`，不会联网。所有测试均在临时目录内运行，不能把合成赛果当成真实比赛结果发布。
